# COPR repositories, one per line: <owner>/<project>[:<priority>]
#
# Lower priority number wins when two repositories offer the same package.
# Default is 99, so anything without a number loses against a numbered one.
#
# --- Why Hyprland needs a COPR at all --------------------------------------
# Hyprland is orphaned in Fedora: the last official build is 0.45.2 on F42 and
# it is absent from F43 and F44 entirely (verified with `dnf repoquery
# --disablerepo="copr*" hyprland` on a real F44 machine — no result).
#
# --- Why sachesi and not solopasha -----------------------------------------
# solopasha/hyprland is the well-known one and it is NOT usable here. Checked
# on 2026-07-31, in a VM, not from memory:
#
#   * its newest Hyprland for F44 is 0.51.1 (as `hyprland-git`; the plain
#     package is 0.49.0 and built only for F41). 0.51 is BEFORE 0.55, so it is
#     still hyprlang — the Lua configuration in this repository would not load
#     at all.
#   * it does not even install: its aquamarine-0.9.5 requires
#     libdisplay-info.so.2, while Fedora 44 ships libdisplay-info 0.3.0 which
#     provides .so.3. The repository was never rebuilt for F44.
#
# sachesi/hyprland carries current Hyprland for fedora-44-x86_64 with a matching
# aquamarine. (At the time of writing it offered 0.55.4, 0.56.0 and 0.56.1; this
# project is developed and verified against 0.55.4, and nothing here pins a
# version, so a fresh install takes whatever is newest.)
# 0.14, hyprutils 0.14, hyprlock 0.9.6, hypridle 0.1.8, hyprpicker 0.4.7 and
# hyprtoolkit 0.5.4, and it resolves cleanly.
#
# solopasha stays enabled at a LOWER priority because it still supplies three
# packages sachesi does not have: uwsm, swww and satty. None of those link
# against hyprutils, so mixing is safe as long as sachesi wins for the core.
sachesi/hyprland:1
solopasha/hyprland:50
